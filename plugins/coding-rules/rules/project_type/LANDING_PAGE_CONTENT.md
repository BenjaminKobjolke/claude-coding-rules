# Landing Page Content Repo Rules

These rules apply to a content repo mounted as the `sites/` submodule of the multi-site PHP
landing-page framework. The framework owns rendering and shared code; this repo supplies each
site's pages, text, settings, styles and assets.

## What a content repo is

A content repo commonly has a root `config.php`, site folders with `{site}/config.php`,
`{site}/templates/index.twig`, `{site}/lang/`, and `_tools/`. Its README says it is mounted by a
framework and does nothing on its own. It has no `composer.json`, application `src/`, or test
suite. Directories beginning with `_` or `.` are tooling or metadata, never sites.

Pair this type with `COMMON_RULES.md` and `DESIGN_RULES.md`; add `SCSS_RULES.md` only when a site
has `{site}/scss/`. Do not pair it with `PHP_RULES.md` or `php/APP.md`: PHP here is limited to
configuration arrays, not an application. The framework itself uses
`project_type/SERVER_RENDERED_FRONTEND.md`.

Common rules still apply to README quality, secrets, DRY, KISS, file length and naming. Rules for
a centralized logger, error handler, integration tests, DTO/constants classes and dependency
versions are framework concerns; do not invent them in a content repo.

## Framework boundary and shared partials

Page sections are shared framework partials. Build each page from its `sections` list, using an
existing partial and only its documented parameters from `docs/partials/PARTIALS.md`.

Never add a site-only section partial or section stylesheet. When no partial fits, ask for a
framework change: add an optional param to the shared partial with a default that preserves
existing sites. Implement that change in the framework repo, through a linked todo or feedback,
not by copying framework code into this repo.

## Page templates

Keep templates to selecting sections and passing their documented params. Put all visible text in
translation keys. Use the framework's asset helpers for URLs; never hand-join asset paths.

## Config arrays

Root `config.php` and `{site}/config.php` return plain arrays. They have no side effects, file or
network I/O, or secrets. Use only keys documented by the framework in `docs/CONFIG.md`; site
configuration overrides only values that differ from root defaults.

## Translations

`en.json` is the source language and `de.json` is hand-maintained. Other locales are generated by
GPT-json-translator, which fills missing keys; do not edit those locales by hand.

- For a new key, add its English and German text, then run the site's translator.
- When changing existing English text, remove the key from the machine-generated locales, then
  re-run the translator so those translations are regenerated.
- The translator batch files end with `pause`; automated runs call their underlying Python
  command directly.

## Assets and media

Keep asset sources in `{site}/public/` and site-root files such as `app-ads.txt` in
`{site}/root/`. The framework mirrors assets into generated, gitignored `public/sites/{site}/`;
never edit that generated copy. After source changes, clear the mirror cache with the framework's
cache-clear tool or URL. Use the site's media tools before committing optimized images.

## Styles

`{site}/scss/` contains site overrides only. The framework compiles SCSS at runtime with scssphp,
so there is no npm, Stylelint or separate build step. Apply `SCSS_RULES.md`'s module, naming,
nesting and token conventions; its Stylelint, npm and build-tool instructions do not apply.

## Deploy and commits

Use the existing `_tools/` and `{site}/tools/` scripts and `.deployignore` conventions. Keep
credentials in the gitignored `_tools/mirror.ini`; commit `mirror.ini.example` without secrets.
Directories beginning with `_` are never sites. Commit content in this repo; update the
`sites/` submodule pointer in a separate framework-repo commit.

## Verification

This repo has no analyzers or test suite. Verify a content change with a page render in the
framework checkout: open every changed site page locally, confirm it returns HTTP 200 with no
Twig error, and check the changed content. When text changed, check English and one
machine-translated language. After asset changes, clear the mirror cache before rendering. Use
the project's screenshot tool when one is configured.

For the optional graphify addon, this is a flat repo: scan `.` and use a root `.graphifyignore` to
exclude content and generated files.
